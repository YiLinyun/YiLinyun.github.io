一次折腾很久的 FCM 推送问题排查：最后发现推送没问题，统计坏了

最近花了挺长时间排查一个 FCM 推送的问题。

问题最开始其实很简单：

Firebase 后台看到的通知展示数（Impressions）和点击数（Opens）越来越低，后来甚至直接变成了 0。

看到这个数据以后，最直观的怀疑当然是：

FCM 推送是不是根本没有正常展示给用户？

但从实际使用情况来看，我一直觉得这个方向不太对。

因为测试设备收通知一直都很正常，基本发送之后很快就能看到，而且我们自己的业务埋点里也一直存在通知点击数据。

只是当时这些都只能算“现象”，一直缺少一份能够直接证明问题到底出在哪一层的证据。

于是整个问题就开始了一轮比较漫长的排查。

一、先确认消息到底有没有送到用户设备

最开始 Firebase 后台只有展示和点击这些结果数据，并不能告诉我们消息到底卡在哪一步。

所以第一步先改了 App，开启 FCM Delivery Metrics 到 BigQuery：

实际统计下来：

大约有 70%~75% 的推送可以成功到达用户设备。

这个数据很重要。

因为至少能证明：

这一段链路并没有整体失效。

于是问题就变成了：

消息明明已经到了设备，为什么 Firebase 后台的展示数还是这么低？

二、然后排查通知权限

下一步自然想到的是：

会不会是消息虽然到了手机，但是用户根本没开通知权限？

如果大量用户关闭通知权限，确实可能出现：

我们 App 本身正好也有通知权限状态的埋点。

查了一下以后发现：

有上万名用户明确开启了通知权限，而且整体开启比例并不低。

当然，这不能证明所有用户都开了权限。

但 Firebase 后台当时的展示数已经低到了个位数，甚至后来变成 0。

这种量级显然不能单纯用“用户没开通知权限”来解释。

到这里，已经能确认两件事情：

理论上应该存在相当数量的真实通知展示。

但 Firebase 后台的数据依然完全对不上。

三、又尝试从点击率证明推送链路正常

除了通知权限埋点，我们自己还有一套推送点击相关的业务埋点。

新用户刚下载安装 App，后续卸载概率比较高。

但另一方面，新用户接收通知的次数比较少，对通知还有一定的新鲜感，所以点击率反而会更高。

但通知看得多了，对同类内容的敏感度降低，点击率也会慢慢下降。

所以至少从用户分层的数据来看，整体表现其实是符合正常使用逻辑的。

四、当时还专门去查了行业点击率

因为单看我们自己的 1%，很难判断它究竟算高还是低。

所以当时我又查了一些公开资料，也询问了 GPT：

再结合 70%~75% 的 MESSAGE_DELIVERED，我觉得现有数据更像是推送链路本身正常，只是 Firebase 的展示、点击统计存在问题。

但经理的判断不一样。

他的核心观点是：

外部报告未必准确，我们自己的埋点也可能不准，Google/Firebase 官方后台的数据应该最可信。

而且竞品的点击率大概有 8%，我们的数据明显偏低，所以还是应该优先怀疑推送功能本身。

我当时的理解则是：

我们的推送效果比竞品差。

但不能直接推出：

这和“FCM 功能有没有正常工作”，其实是两个问题。

不过当时双方判断没有统一，最终还是决定：

以 Google/Firebase 后台的数据为主要依据继续排查。

六、先排查了一次 Notification Channel

经理问客户端：

Notification Channel 确实应该正确注册，但它并不是这次 Firebase 展示、点击统计为 0 的根因。

Channel 这个明显的客户端疑点排除以后，排查重点才正式开始往服务端移动。

前面因为点击率的问题已经讨论了很多，而经理对继续反驳这个方向也表现得有些不耐烦。

毕竟在没有直接证据的情况下：

“服务端更新导致”或者“客户端版本覆盖导致”，本质上都还只是猜测。

既然决定先查服务端，那就用实验去验证。

八、服务端控制变量排查：究竟是哪次改动导致了问题？

既然怀疑问题是从 7 月中旬开始的，那么接下来就开始重新翻服务端 7 月前后所有和 FCM 有关的修改。

这一步不是随机改几个参数试试看。

而是根据历史提交，把可能影响通知展示或者统计的变化逐项拿出来做控制变量。

每一组只改变一个变量，其他东西保持一致。

十六、这次最大的收获

这次排查对我来说最大的经验并不是某一个 Firebase API 怎么使用。

而是：

不要把 FCM 的投递、通知展示和 Firebase 数据统计当成同一件事情。

以后再遇到类似问题，我会优先把整条链路拆开：

然后每一层单独验证。

MESSAGE_DELIVERED

只能证明：

消息已经到达设备上的 FCM SDK。

不能证明通知一定展示。

通知权限

只能证明：

系统允许 App 展示通知。

Showing notification

才可以直接证明：

Android 确实执行了通知展示。

_nr

属于：

Firebase 对通知接收/展示相关 Analytics 事件的记录过程。

Impression / Open

Firebase 后台没有数据，并不等于真实业务行为没有发生。
